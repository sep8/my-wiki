# llm-wiki — agent instructions

This repo is a persistent, LLM-maintained knowledge wiki, following the pattern
in https://gist.github.com/karpathy/442a6bf555914893e9891c11519de94f.

These instructions are agent-agnostic. Claude Code, Codex CLI, GitHub Copilot,
Cursor, and any other coding agent operating in this repo should follow them.

## Bootstrap on a new machine

Agent shims (`.claude/`, `.agents/`, `.github/prompts/`) are
**gitignored** — generate them per machine from `templates/`:

```bash
./setup.sh              # default: claude
./setup.sh codex        # codex only
./setup.sh hermes       # install Hermes bridge skill
./setup.sh claude codex # both
./setup.sh all          # claude + codex + copilot + hermes
```

To update shims after editing `templates/`, just re-run `setup.sh`.

## Layout

```
_raw/<topic>.md     manifest of public source URLs for the topic (tracked in git)
_raw/fetch.sh       downloads manifests into raw/ (idempotent)
raw/<topic>/        immutable sources (PDFs, articles, notes) — gitignored,
                    regenerated locally via `./_raw/fetch.sh <topic>`
wiki/<topic>/       LLM-generated entity & concept pages (markdown)
  index.md            catalog of pages in this topic, grouped by section
  contradictions.md   cross-source tensions within this topic
wiki/log.md         append-only chronological record across all topics
wiki/shared/        (optional) concepts referenced by ≥2 topics; promote here
templates/          source of truth for agent shims (tracked in git)
setup.sh            generates per-agent shims from templates/

# Generated by ./setup.sh (gitignored — regenerate per machine):
.claude/            Claude Code shims (commands/, skills/)
.agents/skills/     Codex workflow skills and query-wiki (auto-discovered)
.github/            GitHub Copilot shims (copilot-instructions.md, prompts/)
$HERMES_HOME/skills/my-wiki/  Hermes bridge skill (generated locally; default ~/.hermes)
```

## Page conventions

- One concept per file. Filename is `kebab-case`, no path or extension when linked.
- Cross-link with `[[brackets]]`. A link to a file that doesn't exist yet is a
  TODO marker for a future page, not an error.
- Every page has: short summary, explanation, related `[[links]]`, and (when
  applicable) a `Contradictions` section pointing to `contradictions.md`.
- Keep pages concise (typically <100 lines). If a page grows past that, split it.

## Topics

- Topics are folders, not tags. A page lives in exactly one topic.
- When ingesting a source that doesn't fit any existing topic, propose a new
  topic folder before writing.
- If a concept gets referenced by ≥2 topics, promote it to `wiki/shared/` and
  relink. Linting flags this.

## Index & contradictions

- `wiki/<topic>/index.md` groups pages by section (e.g. "Architecture",
  "Pre-training paradigms", "Alignment"). Update it whenever pages are
  added/renamed/removed.
- `wiki/<topic>/contradictions.md` records claims that disagree across sources
  in this topic. Each entry: the claim, the sources, brief reconciliation.

## Log

`wiki/log.md` is append-only. Every ingest / lint / non-trivial query appends
one line. Format:

```
- YYYY-MM-DD  <workflow>  <topic>  — one-line summary
```

Don't edit prior entries. If something is wrong, append a correction.

## What goes in wiki/ vs raw/

- `raw/`: never edited after ingest. Original PDFs, html dumps, transcripts.
- `wiki/`: everything generated or written by the LLM/user — summaries,
  syntheses, Q&A pages, decision notes.

## Workflows

Each agent surface exposes these workflows differently, but the contracts
are identical.

| Workflow       | Claude Code                 | Codex CLI                    | GitHub Copilot              | Hermes Agent | When to run                                                                |
| -------------- | --------------------------- | ---------------------------- | --------------------------- | ------------ | -------------------------------------------------------------------------- |
| `fetch-raw`    | `/fetch-raw [topic]`        | `$fetch-raw [topic]`         | `/fetch-raw [topic]`        | Explicit request after `hermes --skills my-wiki` | Download public sources listed in `_raw/<topic>.md` into `raw/<topic>/`    |
| `init-wiki`    | `/init-wiki [topic]`        | `$init-wiki [topic]`         | `/init-wiki [topic]`        | Explicit request after `hermes --skills my-wiki` | Bootstrap a topic from its `raw/` sources                                  |
| `new-wiki`     | `/new-wiki`                 | `$new-wiki`                  | `/new-wiki`                 | Explicit request after `hermes --skills my-wiki` | A new source was added under `raw/<topic>/`                                |
| `linting-wiki` | `/linting-wiki [topic]`     | `$linting-wiki [topic]`      | `/linting-wiki [topic]`     | Explicit request after `hermes --skills my-wiki` | Periodic audit (orphans, broken links, drift, contradictions)              |
| `drop-wiki`    | `/drop-wiki <topic>`        | `$drop-wiki <topic>`         | `/drop-wiki <topic>`        | Explicit request after `hermes --skills my-wiki` | Delete a topic entirely (manifest + raw + wiki); requires confirmation     |
| `export-topic` | `/export-topic ...`         | `$export-topic ...`          | `/export-topic ...`         | Explicit request after `hermes --skills my-wiki` | Copy one curated topic into a code repo for coding-agent use               |
| `query-wiki`   | auto-triggered skill        | auto-triggered skill         | inline rule + `/query-wiki` | Explicit request after `hermes --skills my-wiki` | User asks a question whose subject overlaps an ingested topic              |

Detailed contracts:

### fetch-raw
Run `./_raw/fetch.sh [<topic> ...]`. Reads `_raw/<topic>.md` (markdown manifest
with `- [label](url) → filename` lines) and downloads each URL into
`raw/<topic>/`. Idempotent — skips files already present. If a new topic is
being added, create `_raw/<topic>.md` first.

For non-public sources (private docs, internal PDFs), drop them directly into
`raw/<topic>/` — they stay local since `raw/` is gitignored.

### init-wiki
Read papers in `raw/<topic>/` and create entity pages under `wiki/<topic>/`.
If no topic is given, infer one from the papers and create both folders (moving
PDFs into `raw/<topic>/` as needed). Produce `index.md` and `contradictions.md`.
Append a log line.

### new-wiki
Read the new source alongside existing pages in `wiki/<topic>/`. Update
affected pages, create pages for new concepts, refresh the index, flag
contradictions. If the source doesn't fit any existing topic, propose a new
topic folder before writing. Append a log line.

### linting-wiki
Audit either a single topic or all topics. Identify: orphan pages, missing
pages, broken links, cross-topic promotion candidates, contradictions, stale
claims, index drift. Apply confident fixes; surface the rest. Append a log line.

### drop-wiki
Remove a topic entirely: `_raw/<topic>.md`, `raw/<topic>/`, `wiki/<topic>/`.
Before deleting, list scope and grep for cross-topic `[[brackets]]` that would
become orphans. Require explicit user confirmation in the conversation. After
deletion, sweep dangling cross-topic links in remaining topics. Append a log
line.

### export-topic
Copy one curated topic from `wiki/<topic>/` into a code repository so coding
agents can use it as local project knowledge. Run:

```
./scripts/export-topic.sh <topic> <target-repo> [dest-dir] [options]
```

Default destination is `docs/llm-wiki/<topic>/` inside the target repo. The
script copies only curated wiki pages, writes an `AGENTS.snippet.md`, and can
optionally install a `query-vendored-wiki` skill or append the snippet to the
target repo's `AGENTS.md`.

Do not copy `raw/<topic>/` or `_raw/<topic>.md` unless the user explicitly asks
for source archival.

### query-wiki (auto-engage)
Defined as a skill at `.agents/skills/query-wiki/SKILL.md`. Claude Code reads it
via `.claude/skills/query-wiki/SKILL.md` (symlink); Codex auto-discovers it from
`.agents/skills/`; both engage by description match. GitHub Copilot doesn't
support skill auto-trigger, so the same rule is duplicated inline in
`.github/copilot-instructions.md` and `.github/prompts/query-wiki.prompt.md`.

Hermes automatically loads this repository's `AGENTS.md` when started from
the repository root. Its generated `my-wiki` bridge is intentionally loaded
with `hermes --skills my-wiki`; it routes each named workflow to the canonical
templates rather than defining custom slash commands or duplicating workflow text.

When the user asks a substantive question whose subject overlaps a topic in
`wiki/`, prefer the wiki over re-deriving from training knowledge:

1. List `wiki/` subdirectories; read `wiki/<topic>/index.md` for candidates.
2. Pull the relevant pages; follow `[[brackets]]` one hop when load-bearing.
3. Check `contradictions.md` — surface known tensions explicitly.
4. Answer with citations (`wiki/<topic>/<page>.md`, line numbers when pointing
   at a specific claim).
5. Note gaps where the wiki is silent — don't paper over with training data
   without flagging.
6. If the answer synthesizes something new (comparison, worked example,
   clarification), offer to file it back as a page or section.
7. Log non-trivial queries (those that wrote back or surfaced new contradictions)
   in `wiki/log.md`.

Do NOT auto-engage for meta-questions about the tooling, casual chit-chat, or
coding tasks unrelated to the wiki's subject domain.
