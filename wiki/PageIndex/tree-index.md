# Tree Index (PageIndex Tree)

## Summary
A JSON-based hierarchical Table of Contents that PageIndex generates from a document. Each node is a logical section (chapter, paragraph, page) with metadata, an optional summary, and child nodes. Serves as the structural index for [[reasoning-based-rag]].

## Explanation

### Schema
```js
Node {
  node_id: string,         // unique identifier — also a pointer to raw content
  name: string,            // human-readable title
  description: string,     // optional explanation
  metadata: object,        // arbitrary key-value (type, author, tags, ...)
  sub_nodes: [Node]        // recursive children
}
```

### Concrete example (from API response)
```json
{
  "node_id": "0006",
  "title": "Financial Stability",
  "start_index": 21,
  "end_index": 22,
  "summary": "The Federal Reserve ...",
  "sub_nodes": [
    { "node_id": "0007", "title": "Monitoring Financial Vulnerabilities", ... },
    { "node_id": "0008", "title": "Domestic and International Cooperation ...", ... }
  ]
}
```

### Key properties
- `node_id` is a reference key — it maps to the raw text/images/tables for that node: `node_id → node_content`.
- `sub_nodes` enables recursive nesting → forms the full ToC tree.
- The tree is generated by [[document-processing-api]] (`POST /doc/`) for PDFs or `POST /markdown/` for markdown files.
- Trees can be retrieved with `?type=tree` and optional `summary=true` for per-node summaries.

The tree is *not* stored externally like a vector DB; it is fed directly into the LLM's context — see [[in-context-index]].
